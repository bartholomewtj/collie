Add desktop mode's keydown mapper per `specs/desktop-mode-spec.md` §3 "Keydown mapper" (read the spec's "Decisions" table first — do not re-open those). When `useDesktop().on` and direct typing is armed, a mapper replaces `keyForKeyDown` with these rules: `event.isComposing || keyCode === 229` → do nothing; AltGr (`ctrlKey && altKey` or `getModifierState("AltGraph")`) → treat as no modifier and fall through to the input path; printable with no modifier → existing input/change path; `Enter`, `Backspace`, `Tab`, `Escape`, arrows, `F1`–`F12`, `" "` → `Space` as named keys; Ctrl / Alt / Meta held → `composeKey(mods, base)` with `base` = named key or the lower-cased single-char `event.key`, `shift` added from `event.shiftKey` (`ctrl+shift+p`, `ctrl+Space`, `ctrl+[`, `shift+Tab`), Meta → `cmd`; `preventDefault()` on every key sent, never on keys not sent; kept by the browser (not sent): Ctrl+C with a non-collapsed selection in the mirror, Ctrl+R / Ctrl+Shift+R / F5, and the global chords Ctrl+` and Ctrl+Alt+Up/Down; `Home`, `End`, `PageUp`, `PageDown`, `Insert`, `Delete` are not sent and a status line says "Herdr can't send Delete" (naming the key); bare `Alt` keydown and keyup are `preventDefault`ed while captured; Ctrl+C (no selection), Ctrl+D, Ctrl+Z send immediately with no confirm, and Ctrl+D shows a status. While captured, digits go to the pane raw.
